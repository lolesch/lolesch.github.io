# CV Palette and Type Roles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the zinc/amber placeholder palette with the CV palette, add a `capability` colour and eleven typographic roles, migrate every call site onto them, and close the two gaps the spec names: two Semantic colours that render nowhere on the site, and a type layer that names sizes instead of jobs.

**Architecture:** Nothing new is invented. The palette drops into the `accent` / `accent-inverse` split the Brand layer already has. The type layer gains one new Semantic family, `type`, whose tokens are `--ds-type-<role>-<property>` and which reference the existing `--ds-text-*` ramp plus four new Primitive groups. The adapter gains one Tailwind v4 `@utility` per role. When the last call site is migrated, the bare `--text-*` bridge comes out of `@theme inline` and a fifth discipline rule bans the four loose type properties, so a component chooses a role or nothing.

**Tech Stack:** Next.js 16.2.12 (App Router, `output: 'export'`, `trailingSlash: true`), React 19.2.4, TypeScript ^5, Tailwind CSS ^4 via `@tailwindcss/postcss`, Style Dictionary 5.5.0, Vitest ^4, Node 24.16.0. No new dependencies.

**Source spec:** `docs/superpowers/specs/2026-08-01-cv-palette-and-type-roles-design.md`. Approved by Leonid on 2026-08-01. Read it before starting. Its decisions are settled; the three places this plan goes beyond it are listed under Deviations below and are flagged again at the task that makes them.

## Deviations from the spec, decided rather than deferred

Each is a place the spec's nine roles do not cover a call site that exists. Leonid can cut any of the three at plan review; the tasks that add them are self-contained.

1. **Eleven roles, not nine.** `wordmark` exists because `src/components/site-header.tsx:13` is `font-serif text-body`, a serif at body size that no listed role produces. `code` exists because four `<code>` elements on `/design-system` and one chip in the Rollhaus figure get monospace from Tailwind's preflight today, and applying `type-meta` to them would silently set them in the sans family. The alternatives were losing the serif wordmark, losing the monospace specimens, or leaving five call sites outside a rule whose whole purpose is that nothing is outside it.
2. **A fourth new Primitive group, `font.family`.** The spec lists three (`weight`, `leading`, `tracking`) but its own role table has a family column and its adapter snippet reads `var(--ds-type-heading-family)`. The column needs a source.
3. **`type-eyebrow` carries `text-transform: uppercase`.** It is the one declaration in the adapter that is a literal rather than a `var(--ds-*)`. A role that produces four fifths of a look invites the last fifth to be improvised, which is the failure being fixed. Rejected: leaving `uppercase` at the four call sites, which keeps the adapter purely token-referencing at the cost of a role that is not the whole pattern.

Two further decisions the spec implies but does not spell out:

4. **Where `accent` renders.** Inline and standalone text links get `text-accent`: the two contact links, the CV link, "Back to all work", and the current nav link. The wordmark and the card-title link stay `fg`. Colouring a card title would turn the work grid into a list of links, and the assembled mockup Leonid approved put gold on the active nav link and on an inline prose link only. The current nav link keeps its underline, so colour is never the only cue (SC 1.4.1).
5. **`muted` on `surface` joins `CONTRAST_PAIRS`.** The Rollhaus figure has filled its step panels with `bg-surface` and captioned them in `text-muted` since 2026-07-31. On the zinc palette that pair measured 4.40:1 in light, under AA, and shipped, because three comments in the repo asserted that nothing renders on `surface`. The CV palette clears it at 7.54:1. Listing it is what stops the next palette shipping the same way.
