# Walking Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Get a real Next.js static export live at `https://lolesch.github.io` carrying the approved hero copy, with one complete vertical slice of the token pipeline (DTCG → Style Dictionary → CSS custom properties → Tailwind v4 `@theme` → rendered HTML) and a working theme toggle, tested at Seams 1 and 2 and deployed by GitHub Actions.

**Architecture:** A tracer bullet, not a layer. It pierces every layer of ADR-0003's stack with a deliberately small token set, so the whole pipeline is proven working and deployed before it is widened. Tokens are authored as DTCG JSON in three layers (Primitive → Brand → Semantic), compiled by Style Dictionary into `--ds-*` CSS custom properties with `outputReferences: true` so the layer chain stays visible in the generated artifact, then bridged into Tailwind v4 via `@theme inline`. Dark mode re-declares only the Semantic layer under `[data-theme="dark"]`, which is what makes a future third theme cost zero component changes.

**Tech Stack:** Next.js 16.2.12 (App Router, `output: 'export'`), React 19.2.4, TypeScript ^5, Tailwind CSS ^4.3.3 via `@tailwindcss/postcss`, Style Dictionary ^5.5.0, Vitest ^4.1.10, Node 24.16.0.

## Global Constraints

Every task's requirements implicitly include this section.

**Versions (verified 2026-07-30, not assumed):**
- `next` 16.2.12, `react` / `react-dom` 19.2.4, `typescript` `^5`. **Do not install `typescript@7`** even though it is npm `latest` (7.0.2). Next 16's own generator pins `^5`; TS 7 compatibility with Next 16 is unverified.
- `tailwindcss` `^4`, `@tailwindcss/postcss` `^4` (4.3.3 current), `style-dictionary` `^5` (5.5.0 current), `vitest` `^4`.
- Node 24.16.0 locally and in CI.

**Hosting (ADR-0001):**
- `output: 'export'` in `next.config.ts`.
- **No `basePath` and no `assetPrefix`.** `lolesch.github.io` is a GitHub *user site* served from the domain root. `basePath` is only needed for project pages, and setting it here breaks every asset path.
- `public/.nojekyll` is **required**. Without it GitHub Pages silently drops every path beginning with `_`, which includes Next's entire `_next/` bundle directory. The site would deploy and render unstyled with no JS.

**Token architecture (ADR-0002, ADR-0003):**
- Exactly three layers: Primitive → Brand → Semantic. No Component layer.
- Style Dictionary `prefix: 'ds'`, so generated variables are `--ds-*`. This is non-negotiable: it prevents collision with Tailwind's own `--color-*` / `--font-*` / `--spacing-*` theme namespaces.
- `outputReferences: true` on every CSS file. The Primitive → Brand → Semantic chain must remain readable as nested `var()` calls in the output. That legibility is a deliverable, not a side effect.
- **Components consume Semantic tokens only.** No `--ds-primitive-*` or `--ds-brand-*` may appear anywhere under `src/` outside `src/styles/generated/`. Task 2 enforces this with a test.
- Tokens are authored in DTCG (`$value` / `$type`). Style Dictionary 5.5 auto-detects DTCG; no `usesDtcg` flag is needed.
- Generated CSS is **gitignored**, never hand-edited, and regenerated by a `prebuild` / `pretest` hook.

**Copy (see `CLAUDE.md` → Content guardrails):**
- The hero copy in Task 3 is **approved and frozen**. Reproduce it character for character. Do not reword, retitle, or "tighten" it.
- No em-dashes in any user-visible text.
- Claim only what ships. This plan builds no Figma sync, so nothing in it may reference one.

**Do not touch:** `CLAUDE.md`, `CONTEXT.md`, `_build-log.md`, `docs/adr/**`, `docs/agents/**`. These are authored project records. In particular, **do not run `create-next-app` in this repo**: its template ships its own `CLAUDE.md`, `AGENTS.md`, and `README.md`, which would collide with or clobber the project instructions. Task 1 hand-creates the scaffold instead.

**Accessibility:** WCAG 2.2 AA. Every foreground/background token pair used in Task 3 must clear 4.5:1 in both themes.

## Verified spikes

These were run before the plan was written. The code below is copied from working output, not composed from documentation.

**Spike 1 — three-layer DTCG → CSS variables (Style Dictionary 5.5.0).** Confirmed the layer chain survives into the output:

```css
:root {
  --ds-primitive-neutral-0: #ffffff;
  --ds-brand-paper: var(--ds-primitive-neutral-0);
  --ds-color-bg: var(--ds-brand-paper);
}
```

…and that a dark build filtered to the Semantic layer emits only the override:

```css
[data-theme="dark"] {
  --ds-color-bg: var(--ds-brand-ink);
}
```

**Spike 2 — Tailwind v4 bridge.** Confirmed `@theme inline { --color-bg: var(--ds-color-bg); }` compiles to a utility that references the DS variable directly, so `[data-theme]` overrides work with no component involvement:

```css
.bg-bg { background-color: var(--ds-color-bg); }
```

Note the `inline` keyword is load-bearing. Without it Tailwind emits its own `--color-bg` at `:root` and utilities point at *that*, which the `[data-theme="dark"]` block would not override. Next 16's default scaffold uses `@theme inline` for the same reason.

**Spike 3 — filtered-reference warning.** The dark build legitimately references Brand tokens it does not emit, and Style Dictionary warns about it on every run. `log: { warnings: 'disabled' }` at platform level silences it. This is intentional, not a papered-over bug: the reference resolves at CSS cascade time against the `:root` block.

- [ ] **Step 1: Write the failing Seam 1 test**

Create `tests/unit/tokens.test.ts`:

```ts
import { readFileSync } from 'node:fs';
import { describe, expect, it } from 'vitest';

const light = readFileSync('src/styles/generated/tokens.css', 'utf8');
const dark = readFileSync('src/styles/generated/tokens.dark.css', 'utf8');

describe('token pipeline (Seam 1)', () => {
  it('emits all three layers into :root', () => {
    expect(light).toContain(':root {');
    expect(light).toMatch(/--ds-primitive-/);
    expect(light).toMatch(/--ds-brand-/);
    expect(light).toMatch(/--ds-color-/);
  });

  it('keeps the layer chain visible as nested var() calls', () => {
    // This is also the propagation guarantee the PRD asks for: because Semantic
    // points at Brand by reference rather than by value, any Brand change
    // propagates through the CSS cascade by construction.
    expect(light).toMatch(/--ds-color-bg:\s*var\(--ds-brand-paper\)/);
    expect(light).toMatch(/--ds-brand-paper:\s*var\(--ds-primitive-neutral-0\)/);
  });

  it('re-declares only the Semantic layer for dark', () => {
    expect(dark).toContain('[data-theme="dark"]');
    expect(dark).toMatch(/--ds-color-bg:\s*var\(--ds-brand-ink\)/);
    // No Primitive is referenced or declared in the dark override at all.
    expect(dark).not.toMatch(/--ds-primitive-/);
    // Brand may be *referenced* by dark, but never *declared* there.
    expect(dark).not.toMatch(/--ds-brand-[\w-]+:/);
  });

  it('gives light and dark identical Semantic keys, so no component branches on theme', () => {
    const keys = (css: string) =>
      [...css.matchAll(/(--ds-color-[\w-]+):/g)].map((m) => m[1]).sort();
    const lightSemantic = keys(light).filter((k) => k.startsWith('--ds-color-'));
    expect(keys(dark)).toEqual(lightSemantic);
  });
});
```

- [ ] **Step 6: Replace `scripts/build-tokens.mjs`**

Delete the Task 1 stub and write:

```js
import StyleDictionary from 'style-dictionary';

const buildPath = 'src/styles/generated/';

// Every build sees the full Primitive + Brand graph plus theme-independent
// semantics. Only the theme-specific colour file changes between the two.
const base = [
  'tokens/primitive/**/*.json',
  'tokens/brand/**/*.json',
  'tokens/semantic/space.json',
];

const platforms = (destination, selector, filter) => ({
  css: {
    transformGroup: 'css',
    prefix: 'ds',
    buildPath,
    // The dark build intentionally references Brand tokens it does not emit;
    // they resolve against :root at cascade time. Silence the expected warning.
    log: { warnings: 'disabled' },
    files: [
      {
        destination,
        format: 'css/variables',
        filter,
        options: { outputReferences: true, selector },
      },
    ],
  },
});

// Light: emit all three layers under :root.
const light = new StyleDictionary({
  source: [...base, 'tokens/semantic/color.light.json'],
  platforms: platforms('tokens.css', ':root'),
});

// Dark: emit ONLY the semantic colour overrides.
const dark = new StyleDictionary({
  source: [...base, 'tokens/semantic/color.dark.json'],
  platforms: platforms('tokens.dark.css', '[data-theme="dark"]', (token) =>
    token.filePath.includes('color.dark'),
  ),
});

await light.buildAllPlatforms();
await dark.buildAllPlatforms();
```

- [ ] **Step 9: Write the token-discipline test**

This is the architectural rule from PRD user story #9, enforced rather than asserted in prose. Create `tests/unit/token-discipline.test.ts`:

```ts
import { globSync, readFileSync } from 'node:fs';
import { describe, expect, it } from 'vitest';

// The generated stylesheets are where Primitive and Brand legitimately live.
const GENERATED = 'src/styles/generated/';

describe('token discipline', () => {
  it('never reaches past the Semantic layer from application code', () => {
    const files = globSync('src/**/*.{ts,tsx,css}').filter(
      (f) => !f.replaceAll('\\', '/').includes(GENERATED),
    );

    expect(files.length).toBeGreaterThan(0);

    for (const file of files) {
      const source = readFileSync(file, 'utf8');
      const offenders = source.match(/--ds-(primitive|brand)-[\w-]+/g) ?? [];
      expect(
        offenders,
        `${file} reaches past the Semantic layer: ${offenders.join(', ')}`,
      ).toEqual([]);
    }
  });
});
```

`globSync` comes from Node's built-in `fs` (Node 22+), so this needs no extra dependency. The `replaceAll('\\', '/')` normalises Windows path separators.

```tsx
};

// Runs before first paint so the correct theme is on <html> with no flash.
// Inline because a deferred module would paint the wrong theme first.
const themeInit = `
(function () {
  try {
    var stored = localStorage.getItem('theme');
    var dark = window.matchMedia('(prefers-color-scheme: dark)').matches;
    document.documentElement.dataset.theme = stored || (dark ? 'dark' : 'light');
  } catch (e) {
    document.documentElement.dataset.theme = 'light';
  }
})();
`;

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" data-theme="light" suppressHydrationWarning>
      <head>
        <script dangerouslySetInnerHTML={{ __html: themeInit }} />
      </head>
      <body className={`${headline.variable} ${body.variable} font-sans`}>
        {children}
      </body>
    </html>
  );
}
```

`data-theme="light"` is set in the markup so the static HTML is never theme-less, which is what the Seam 2 assertion checks. The inline script corrects it before paint. `suppressHydrationWarning` is needed because that script mutates the attribute the server rendered.

Create `src/components/theme-toggle.tsx`:

```tsx
'use client';

import { useEffect, useState } from 'react';

type Theme = 'light' | 'dark';

export function ThemeToggle() {
  const [theme, setTheme] = useState<Theme | null>(null);

  // Read what the pre-paint script already decided, rather than deciding again.
  useEffect(() => {
    setTheme((document.documentElement.dataset.theme as Theme) ?? 'light');
  }, []);

  function toggle() {
    const next: Theme = theme === 'dark' ? 'light' : 'dark';
    document.documentElement.dataset.theme = next;
    localStorage.setItem('theme', next);
    setTheme(next);
  }

  return (
    <button
      type="button"
      onClick={toggle}
      // aria-pressed is omitted until the client knows the real theme, so the
      // button never announces a state that contradicts what is on screen.
      aria-pressed={theme === 'dark' ? true : theme === 'light' ? false : undefined}
      className="rounded border border-border px-2 py-1 text-sm text-muted hover:text-fg hover:border-fg"
    >
      {theme === 'dark' ? 'Light' : 'Dark'} mode
    </button>
  );
}
```

- [ ] **Step 2: Write the workflow**

Create `.github/workflows/deploy.yml`:

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

# Never let two deploys race. Do not cancel a running deploy mid-flight.
concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: '24'
          cache: npm

      - run: npm ci

      # Seam 1 + token discipline. A broken token architecture fails the deploy.
      - run: npm test

      - run: npm run build

      # Seam 2, against the artifact that is about to ship.
      - run: npx vitest run tests/export

      - uses: actions/configure-pages@v5

      - uses: actions/upload-pages-artifact@v3
        with:
          path: out

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

The workflow runs `npm run build` and `npx vitest run tests/export` as separate steps rather than `npm run test:export`, so a build failure and an assertion failure show up as different red steps in the CI log.
